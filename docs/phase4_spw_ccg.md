# 阶段4：跨预算场景池热启动 SPW-C&CG

## 1. 目标

阶段4在阶段3标准有限场景 C&CG 的基础上，实现预算序列之间的场景池复用。对严格递增的预算
\(B_1<\cdots<B_m\)，每个预算同时运行：

1. 冷启动标准 C&CG；
2. 场景池热启动 SPW-C&CG。

两者使用同一完整候选场景集、精确补救 oracle、求解器、容差和最大迭代次数。热启动只改变受限主问题的初始场景池，不删减 oracle，也不传递求解器变量初值。

## 2. 场景池

首个预算的冷、热算法都使用阶段3基础场景。预算 \(B_j\) 的热启动池为

\[
\Omega^0_j=
\Omega^{base}
\cup\Omega^{active}_{j-1}
\cup\Omega^{history}_{j-1}.
\]

- `base`：均值邻近、最高总需求、最高平均应急价格和最低总应急供应场景；
- `active`：上一预算最终精确评价中，补救成本与最坏补救成本之差不超过 `active_scenario_tolerance` 的场景；
- `history`：此前热启动迭代中加入过的不可行/最坏场景以及各预算最终最坏场景的累积集合。

同时保存上一预算的最终主问题场景集用于诊断，但第一版不把整个最终集合无条件复制到下一预算，避免热池持续膨胀。

## 3. 精确性

热启动池始终是完整有限场景集的子集，其中每个场景都是原鲁棒模型的有效场景。后续每次迭代仍对全部场景独立求解精确补救问题。因此，热启动只使初始受限主问题更紧，不改变完整问题的可行域或最优目标。

每个预算必须满足：

\[
|z^{cold}_j-z^{warm}_j|
\le \epsilon_{abs}
+\epsilon_{rel}\max(1,|z^{cold}_j|,|z^{warm}_j|).
\]

任何预算下冷、热算法不收敛或目标超差，阶段4结果都不得标记为通过。

## 4. 公平计时

- 预算按升序求解；
- 相邻预算交替使用 `cold->warm` 和 `warm->cold` 执行顺序；
- 热启动总时间包含场景池构造时间；
- 冷启动也单独记录基础池构造时间；
- 分别报告总时间、主问题时间、oracle 时间、迭代数、初始池和最终池大小；
- 单次小样本结果只用于正确性验证，论文性能结论需要多随机种子并报告中位数与四分位区间。

## 5. 输出

- `outputs/solutions/phase4/spw_ccg_results.json`：完整冷/热结果与传递状态；
- `outputs/tables/phase4/budget_comparison.csv`：逐预算目标、迭代和时间对比；
- `outputs/tables/phase4/scenario_pool_transfer.csv`：逐场景的池成员与活跃/历史标记；
- `outputs/logs/phase4/ccg_iterations.csv`：全部预算、冷/热模式的逐迭代日志。

## 6. 已知限制

- 当前 oracle 仍为串行枚举；
- 第一版只研究场景池 warm start，不研究变量初值；
- 不裁剪历史对抗场景；
- 当前正式输出是单种子小规模正确性实验，不能单独支持统计显著的加速结论；
- 严格 FIFO、路径、机器学习、连续预算不确定集和分布鲁棒优化不属于本阶段。
