# 阶段6正式实验矩阵

候选版本：`phase6_formal_experiments_v1_1`

初稿日期：2026-07-24；复审修订：2026-07-27

机器可读配置：`configs/phase6_experiment_matrix.yaml`

当前状态为“待复审冻结候选”。只有 PR 审查通过并合并后才能称为正式冻结；在此之前不得运行正式训练或测试种子。

## 1. 目的与边界

阶段1–5已经完成小规模正确性、工程状态和可复现性验证。阶段6不再修改核心数学约束，其任务是用预先冻结的实验设计回答：

1. 内生储备机制相对确定性、零储备和固定比例策略是否改善决策质量；
2. 标准 C&CG 相对全场景扩展式能扩展到多大规模；
3. SPW-C&CG 是否在保持精确性的前提下减少迭代和时间；
4. 上述结论能否在独立样本外场景和真实数据校准后保持；
5. 方法在什么风险、库存和预算条件下有效、无效或超时。

实验可以支持“在本实验范围内有效”的结论，不能仅凭数值结果宣称未经文献检索证明的“首次”。

## 2. 预注册研究假设

- **H1 结构正确性门槛**：在相同完整训练场景和预算下，内生储备鲁棒模型的精确重评价目标不劣于被测试的固定比例策略。这主要来自可行域包含关系，作为正确性检查，不作为实证创新结论。
- **H2 样本外价值**：内生储备在至少一类非基准风险设置下改善样本外缺货、尾部成本或两者之一；若没有改善，应如实报告。
- **H3 精确热启动**：每个成功配对实例中，SPW-C&CG 与标准冷启动 C&CG 的目标和第一阶段可行性在冻结容差内一致。
- **H4 计算效率**：SPW-C&CG 的配对迭代次数中位数低于冷启动；总时间是否降低由实验决定，不预设必然成立。
- **H5 场景持续性**：相邻预算活跃场景集合的 Jaccard 相似度与热启动收益具有正向关系；该关系是待检验假设，不作为算法前提。
- **H6 机制方向**：需求波动、应急价格、供应收缩、保质期和容量会系统改变最优储备比例，但不预先强制单调结论。

## 3. 三条数据轨道

### 3.1 受控合成数据

用于正确性、规模、算法计时和机制识别，是阶段6必做轨道。遗留 `D0` 档保持阶段3参数不变；其余档位使用支持任意时期数、物资异质性、共同灾害因子和物资特有噪声的阶段6生成器。

多物资档位使用五个固定原型，需求倍率为 `1.00/0.75/0.50/0.35/0.25`，常规价格倍率为 `1.00/1.20/1.50/2.00/2.50`，保质期为 `6/4/3/2/1`。档位含 \(K\) 种物资时使用前 \(K\) 个原型，避免用完全相同物资机械复制规模。

### 3.2 真实数据校准的合成数据

用于外部有效性，是论文阶段6最终结论的必做轨道，但当前状态为“等待独立校准协议”。真实灾害影响、食品价格、采购公告和供应/物流代理变量只用于估计参数、相关性和边界，再从冻结后的分布生成独立训练集与测试集。本轨道暂不计入 `v1_1` 的受控合成计算量，待校准协议单独审查后追加工作量。

执行前必须单独冻结：

- 数据来源、许可、访问日期和原始文件哈希；
- 地区、灾害类型、物资和时间粒度；
- 缺失值与异常值规则；
- 需求、价格和供应代理变量的转换公式；
- 训练事件与测试事件的时间或事件级隔离规则。

不得按行随机拆分同一灾害事件，以免信息泄漏。

### 3.3 历史案例

历史案例用于解释模型，不替代受控性能实验。只有在需求、价格和供应代理均可追溯时才执行；缺少真实供应上限时必须明确标为估计值。

## 6. 预算设计

多物资和多时期下不直接复用绝对预算，而定义参考预算：

\[
B_{\mathrm{ref}}
=
\sum_{k,t}c^0_{kt}\mathbb{E}[d_{kt}].
\]

其中 \(\mathbb{E}[d_{kt}]\) 必须使用冻结场景生成器的理论期望，不使用某个训练种子的样本均值，避免预算本身随随机种子变化。

正式预算为：

\[
B=\beta B_{\mathrm{ref}},
\qquad
\beta\in\{0.75,0.90,1.00,1.10,1.25,1.40\}.
\]

敏感性分析使用 \(\beta\in\{0.90,1.10,1.30\}\)。`D0` 额外保留历史绝对预算 `700–1200`，只用于与阶段5结果衔接，不用于跨规模比较。

预算始终按升序执行。试运行若发现全部预算都返回同一储备状态，只允许在正式种子运行前调整因子，并记录版本变化。

## 7. 实验族

### E0：遗留回归

- 数据：`D0`、种子 `20260723`、绝对预算 `700–1200`；
- 目标：复现阶段3–5结果，确保阶段6代码没有改变既有模型；
- 门槛：扩展式、标准 C&CG、SPW-C&CG保持既有目标一致性。

### E1：金标准一致性

- 档位：`D0/V1/V2`；
- 比较：全场景扩展式与标准 C&CG；
- 预算：正式六档；
- 门槛：目标绝对容差 `1e-5`、相对容差 `1e-7`，全部独立补救必须最优。

`P1` 扩展式只作为限时附加实验；超时不影响 C&CG 正常统计，但必须进入失败表。

### E2：内生储备机制

- 档位：`V1/V2/P1`；
- 种子：每档10个；
- 预算：正式六档；
- 策略：平均场景确定性、零储备、固定比例 `10%/20%/30%/40%/50%`、内生储备；
- 训练场景：同一档位、种子和预算下完全共享；
- 样本外测试：同一实例的所有策略共享同一测试场景。

所有8种策略得到第一阶段方案后，都必须在相同完整训练场景上调用独立精确补救模型重新评价，统一使用

\[
C^0(y)+\max_{\omega\in\Omega}Q_{\mathrm{exact}}(y,R,\omega)
\]

作为训练集比较目标。确定性模型的原生均值场景目标不得直接与鲁棒目标比较。

主要实证比较储备金额与比例、样本外缺货、尾部成本、浪费、应急支出和服务水平。内生模型训练目标不劣于固定比例主要作为结构正确性门槛，不得包装为数值创新发现，也不得只报告内生模型占优的实例。

### E3：标准 C&CG 与 SPW-C&CG 性能

- 档位：`V1–P4`；
- 预算：正式六档，升序；
- 冷/热使用相同完整候选场景 oracle、求解器、线程、容差和时限；
- 冷/热执行顺序交替；
- `V1/V2/P1` 每个配对计时3次，`P2–P4` 计时1次；
- 同一算法、档位、种子和预算的3次技术重复先取中位数，不能当成3个独立统计样本。

冷/热目标不一致的配对不能进入加速结论，但必须保留在失败表并阻断相应正确性结论。

主实验按预算交替执行冷/热配对。若任一算法在某预算出现求解失败、单预算墙钟超时或非最优终止：

1. 保存此前全部成功预算配对；
2. 保存当前预算的迭代日志、上下界、场景池、超时层级和已用时间；
3. 当前不完整场景池不得传递；
4. 该配对序列剩余预算标记为 `not_run_after_pair_sequence_failure`；
5. 命令行非零退出；
6. 主结果不自动重试；诊断重试必须使用独立 run 标识。

E3冻结为1296次算法执行。若平均10次 C&CG 迭代，预计约684万次补救 LP；按200次迭代上限约1.368亿次。仅按单预算墙钟上界计算，E3串行上界约642小时。

因此正式种子启动前必须使用3个试运行种子测量主问题/小时、补救LP/小时、预算配对/小时和峰值内存，并投影 E1–E5 总工时。候选矩阵的计算门槛为：

- E1–E5预计总墙钟不超过720小时；
- 任一实验族预计不超过336小时；
- 超过任一门槛时，必须在正式种子运行前修订并升级矩阵版本，不能运行后再选择性删减。

### E4：独立样本外评价

为控制计算量，主样本外实验冻结为：

- 档位：`V2`；
- 前5个正式训练种子及对应测试种子；
- 预算因子：`0.90/1.10/1.30`；
- 8种策略；
- 每个策略使用5000个独立测试场景；
- 共120个第一阶段方案、600,000次单场景补救评价。

测试场景不得参与调参、场景池构造或重新优化。若扩展更多档位，作为附加实验单独编号，不能替代主实验。

每个方案必须首先报告：

- `optimal_scenario_count`；
- `recourse_feasibility_rate`；
- `infeasible_scenario_count`；
- `solver_failure_count`；
- `plan_oos_status`。

求解器超时、无界、数值错误或未知状态不是“补救不可行”。只有求解器明确证明不可行时才计入 `infeasible_scenario_count`。若 `solver_failure_count>0`，真实补救可行率未知，`recourse_feasibility_rate` 记为空；同时另报 `optimal_scenario_count/5000` 作为最优评价完成率。

`plan_oos_status` 冻结为：

- `complete_feasible`：5000个场景全部最优；
- `contains_infeasible_recourse`：存在已证明不可行且没有求解器失败；
- `incomplete_solver_failure`：存在求解器失败且没有已证明不可行；
- `incomplete_solver_failure_and_infeasible`：两者同时存在。

只有 `complete_feasible` 方案才计算平均值、分位数、CVaR、缺货、服务水平、浪费和应急支出聚合值。出现任一不可行或求解器失败时，这些主聚合指标全部记为空；不得只删除失败场景后计算，也不得用任意 Big-M 伪造总成本。该方案仍完整保留在可行性表和失败表中。

指标公式冻结如下：

- 场景总成本为常规采购成本加精确场景补救成本，`R` 不重复计入；
- 缺货概率为总缺货超过 `1e-7` 的场景比例；
- 场景服务水平为 \(1-\sum shortage/\sum demand\)，总需求为0时定义为1；
- 经验分位数使用线性插值 Type 7；
- CVaR95为最坏5%成本的经验均值，边界不足一个完整观测时使用分数权重；
- 储备利用率为场景应急支出除以 \(R\) 后取均值；当 \(R\le10^{-9}\) 时记为空并设置零储备标志，不把它解释为0%利用率。

### E5：敏感性和交互

单因素分析使用 `V2`、10个正式训练种子、3个敏感性预算，但采用独立冻结的 E5 基准。E5 将 `V2` 第一物资原型的保质期从6期统一覆盖为3期；下表所有23个配置（包括改变其他因素时）都从这一个保质期3的基准出发：

| 因素 | 低 | 基准 | 高 |
|---|---:|---:|---:|
| 需求变异系数 | 0.15 | 0.30 | 0.45 |
| 应急价格平均加价 | 0.15 | 0.35 | 0.55 |
| 应急价格冲击标准差 | 0.05 | 0.15 | 0.25 |
| 平均供应缩减 | 0.05 | 0.20 | 0.40 |
| 供应冲击标准差 | 0.10 | 0.20 | 0.35 |
| 需求—价格相关性 | 0.30 | 0.60 | 0.90 |
| 需求—供应相关性 | -0.20 | -0.45 | -0.70 |
| 保质期 | 1 | 3 | 6 |
| 容量/期望期需求 | 0.50 | 1.50 | 3.00 |
| 缺货惩罚倍率 | 6 | 12 | 24 |
| 浪费惩罚倍率 | 0.10 | 0.25 | 0.50 |

基准组合只计算一次，因此共有23个唯一单因素配置，而不是机械执行33个重复配置；对应690个内生模型求解。

小型交互实验采用预算、需求波动、价格加价和供应缩减四个因素的两水平全因子设计，共16个组合、5个种子，即80个求解。该实验用于发现交互，不替代单因素机制图。

为直接检验易腐库存与灾后市场风险的联合机制，另设“保质期 × 供应缩减”两因素实验：

- 保质期：`1/6`；
- 平均供应缩减：`0.05/0.40`；
- 固定预算因子：`1.10`；
- 前5个正式训练种子；
- 每个种子4个组合，共20个求解。

## 9. 统计方案

- 独立实验单位是训练种子，不是预算，也不是计时重复；
- 同一算法、档位、种子和预算的技术重复先取中位数；
- 固定预算比较以训练种子为重采样单位；
- 汇总六预算时，以训练种子为簇，对同一种子的整条六预算序列一起进行10,000次配对簇 bootstrap；
- 描述统计：样本数、均值、标准差、中位数、四分位区间、最小值和最大值；
- 不确定性报告95%置信区间；
- 可选检验：Wilcoxon配对符号秩检验；
- 多重比较时同时报告效应量和校正后的 \(p\) 值；
- P3的5个种子和P4的3个种子只报告描述统计，不报告置信区间或显著性检验；
- 必须同时报告冷启动完成率、热启动完成率、联合配对完成率，以及联合成功配对上的条件加速比；
- 条件加速比不得脱离上述三种完成率单独报告，失败和超时保留在分母中。

三种完成率的分母分别是计划的全部冷运行、全部热运行和全部冷/热配对；超时、失败以及前序失败导致的未运行预算也保留在计划分母中。

H5 使用相邻预算转换作为观测，活跃场景集合 Jaccard 为解释量，\(\log(t_{\mathrm{cold}}/t_{\mathrm{warm}})\) 为结果量，报告 Spearman 秩相关。置信区间按训练种子做簇 bootstrap，同一种子的全部预算转换一起重采样；只用于关联描述，不使用因果措辞。

## 10. 公平性和运行控制

- 固定求解器版本、单线程和相同容差；
- 单次求解器时限由求解器执行，单预算和六预算墙钟由 runner 外部 watchdog 独立执行；
- oracle 串行作为主结果；若后续实现并行，只能作为独立附加实验；
- 运行期间关闭非必要高负载任务并记录硬件；
- 所有算法使用相同场景、种子和预算；
- 每个 run 保存配置、场景哈希、Git SHA、依赖、硬件、起止时间和终止状态；
- 缓存只能复用完全相同配置哈希的结果；
- 不允许因为结果不理想而更换正式种子。

## 11. 预计主工作量

- E1 金标准：约252个模型求解；
- E2 策略比较：最多1440个训练求解，其中与 E1/E3相同配置应从运行注册表复用；
- E3 冷/热计时：1296次算法执行；10次平均迭代约684万次补救LP，200次上限约1.368亿次；
- E4 样本外：120个方案、600,000次精确补救评价；
- E5：690个唯一单因素求解，加80个市场因素交互和20个库存—供应交互求解；
- E6：数量由独立真实数据校准协议确定，不计入本版总量。

因此阶段6必须支持断点续跑、配置哈希去重、失败诊断和分批执行，并在正式种子前生成试运行吞吐量与总工时投影。不得用一次长脚本覆盖已有结果。

## 12. 阶段门槛

1. `D0/V1/V2` 扩展式与标准 C&CG全部通过一致性门槛；
2. 所有成功冷/热配对目标一致；
3. 训练和测试场景独立且哈希可追溯；
4. P档同时满足80%完成率和中位时间不超过预算墙钟75%后逐级启用；
5. 模型比较、性能、样本外、敏感性和失败表均能由脚本重新生成；
6. 每张图都能追溯到结果 CSV、矩阵版本、种子和代码提交；
7. 真实校准轨道完成来源与变量映射审查；
8. 不把超时、失败或热启动变慢的结果删除。
9. 试运行投影满足 E1–E5总计不超过720小时、单实验族不超过336小时；
10. 样本外不可行和求解失败按冻结状态规则报告，不生成任意惩罚成本。

## 13. 冻结与变更

本候选矩阵只有在 PR 复审通过并合并后才转为“正式冻结”。在正式训练种子首次运行前仍可通过带版本记录的 PR 修订。正式运行开始后，任何预算、种子、档位、指标或容差变化必须：

1. 升级 `matrix_id/schema_version`；
2. 说明原因和受影响实验；
3. 保留旧结果；
4. 不把变更后的结果与原版本无标记混合。
