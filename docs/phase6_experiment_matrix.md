# 阶段6正式实验矩阵

版本：`phase6_formal_experiments_v1`  
冻结日期：2026-07-24  
机器可读配置：`configs/phase6_experiment_matrix.yaml`

## 1. 目的与边界

阶段1–5已经完成小规模正确性、工程状态和可复现性验证。阶段6不再修改核心数学约束，其任务是用预先冻结的实验设计回答：

1. 内生储备机制相对确定性、零储备和固定比例策略是否改善决策质量；
2. 标准 C&CG 相对全场景扩展式能扩展到多大规模；
3. SPW-C&CG 是否在保持精确性的前提下减少迭代和时间；
4. 上述结论能否在独立样本外场景和真实数据校准后保持；
5. 方法在什么风险、库存和预算条件下有效、无效或超时。

实验可以支持“在本实验范围内有效”的结论，不能仅凭数值结果宣称未经文献检索证明的“首次”。

## 2. 预注册研究假设

- **H1 内生储备**：在相同训练场景和预算下，内生储备鲁棒模型的训练集鲁棒目标不劣于被测试的固定比例策略。
- **H2 样本外价值**：内生储备在至少一类非基准风险设置下改善样本外缺货、尾部成本或两者之一；若没有改善，应如实报告。
- **H3 精确热启动**：每个成功配对实例中，SPW-C&CG 与标准冷启动 C&CG 的目标和第一阶段可行性在冻结容差内一致。
- **H4 计算效率**：SPW-C&CG 的配对迭代次数中位数低于冷启动；总时间是否降低由实验决定，不预设必然成立。
- **H5 场景持续性**：相邻预算活跃场景集合的 Jaccard 相似度与热启动收益具有正向关系；该关系是待检验假设，不作为算法前提。
- **H6 机制方向**：需求波动、应急价格、供应收缩、保质期和容量会系统改变最优储备比例，但不预先强制单调结论。

## 3. 三条数据轨道

### 3.1 受控合成数据

用于正确性、规模、算法计时和机制识别，是阶段6必做轨道。遗留 `D0` 档保持阶段3参数不变；其余档位使用支持任意时期数、物资异质性、共同灾害因子和物资特有噪声的阶段6生成器。

多物资档位使用五个固定原型，需求倍率为 `1.00/0.75/0.50/0.35/0.25`，常规价格倍率为 `1.00/1.20/1.50/2.00/2.50`，保质期为 `6/4/3/2/1`。档位含 \(K\) 种物资时使用前 \(K\) 个原型，避免用完全相同物资机械复制规模。

### 3.2 真实数据校准的合成数据

用于外部有效性，是阶段6必做轨道。真实灾害影响、食品价格、采购公告和供应/物流代理变量只用于估计参数、相关性和边界，再从冻结后的分布生成独立训练集与测试集。

执行前必须单独冻结：

- 数据来源、许可、访问日期和原始文件哈希；
- 地区、灾害类型、物资和时间粒度；
- 缺失值与异常值规则；
- 需求、价格和供应代理变量的转换公式；
- 训练事件与测试事件的时间或事件级隔离规则。

不得按行随机拆分同一灾害事件，以免信息泄漏。

### 3.3 历史案例

历史案例用于解释模型，不替代受控性能实验。只有在需求、价格和供应代理均可追溯时才执行；缺少真实供应上限时必须明确标为估计值。

## 6. 预算设计

多物资和多时期下不直接复用绝对预算，而定义参考预算：

\[
B_{\mathrm{ref}}
=
\sum_{k,t}c^0_{kt}\mathbb{E}[d_{kt}].
\]

正式预算为：

\[
B=\beta B_{\mathrm{ref}},
\qquad
\beta\in\{0.75,0.90,1.00,1.10,1.25,1.40\}.
\]

敏感性分析使用 \(\beta\in\{0.90,1.10,1.30\}\)。`D0` 额外保留历史绝对预算 `700–1200`，只用于与阶段5结果衔接，不用于跨规模比较。

预算始终按升序执行。试运行若发现全部预算都返回同一储备状态，只允许在正式种子运行前调整因子，并记录版本变化。

## 7. 实验族

### E0：遗留回归

- 数据：`D0`、种子 `20260723`、绝对预算 `700–1200`；
- 目标：复现阶段3–5结果，确保阶段6代码没有改变既有模型；
- 门槛：扩展式、标准 C&CG、SPW-C&CG保持既有目标一致性。

### E1：金标准一致性

- 档位：`D0/V1/V2`；
- 比较：全场景扩展式与标准 C&CG；
- 预算：正式六档；
- 门槛：目标绝对容差 `1e-5`、相对容差 `1e-7`，全部独立补救必须最优。

`P1` 扩展式只作为限时附加实验；超时不影响 C&CG 正常统计，但必须进入失败表。

### E2：内生储备机制

- 档位：`V1/V2/P1`；
- 种子：每档10个；
- 预算：正式六档；
- 策略：平均场景确定性、零储备、固定比例 `10%/20%/30%/40%/50%`、内生储备；
- 训练场景：同一档位、种子和预算下完全共享；
- 样本外测试：同一实例的所有策略共享同一测试场景。

主要比较目标、储备金额与比例、缺货、浪费、应急支出和服务水平。不得只报告内生模型优于固定比例的实例。

### E3：标准 C&CG 与 SPW-C&CG 性能

- 档位：`V1–P4`；
- 预算：正式六档，升序；
- 冷/热使用相同完整候选场景 oracle、求解器、线程、容差和时限；
- 冷/热执行顺序交替；
- `V1/V2/P1` 每个配对计时3次，`P2–P4` 计时1次；
- 主要统计单位为“同一档位、种子、预算”的配对。

冷/热目标不一致的配对不能进入加速结论，但必须保留在失败表并阻断相应正确性结论。

### E4：独立样本外评价

为控制计算量，主样本外实验冻结为：

- 档位：`V2`；
- 前5个正式训练种子及对应测试种子；
- 预算因子：`0.90/1.10/1.30`；
- 8种策略；
- 每个策略使用5000个独立测试场景；
- 共120个第一阶段方案、600,000次单场景补救评价。

测试场景不得参与调参、场景池构造或重新优化。若扩展更多档位，作为附加实验单独编号，不能替代主实验。

### E5：敏感性和交互

单因素分析使用 `V2`、10个正式训练种子、3个敏感性预算：

| 因素 | 低 | 基准 | 高 |
|---|---:|---:|---:|
| 需求变异系数 | 0.15 | 0.30 | 0.45 |
| 应急价格平均加价 | 0.15 | 0.35 | 0.55 |
| 应急价格冲击标准差 | 0.05 | 0.15 | 0.25 |
| 平均供应缩减 | 0.05 | 0.20 | 0.40 |
| 供应冲击标准差 | 0.10 | 0.20 | 0.35 |
| 需求—价格相关性 | 0.30 | 0.60 | 0.90 |
| 需求—供应相关性 | -0.20 | -0.45 | -0.70 |
| 保质期 | 1 | 3 | 6 |
| 容量/期望期需求 | 0.50 | 1.50 | 3.00 |
| 缺货惩罚倍率 | 6 | 12 | 24 |
| 浪费惩罚倍率 | 0.10 | 0.25 | 0.50 |

基准组合只计算一次，因此共有23个唯一单因素配置，而不是机械执行33个重复配置；对应690个内生模型求解。

小型交互实验采用预算、需求波动、价格加价和供应缩减四个因素的两水平全因子设计，共16个组合、5个种子，即80个求解。该实验用于发现交互，不替代单因素机制图。

### E6：真实数据校准与历史案例

执行顺序：

1. 冻结原始数据和许可；
2. 清洗并生成变量映射报告；
3. 用历史数据估计边际分布、相关性和极值范围；
4. 按事件或时间切分校准集与验证集；
5. 生成与受控实验相同结构的训练和测试场景；
6. 复用 E1–E5 的核心比较，但不把真实校准结果混入纯算法计时主表；
7. 若数据完整，再加入一个历史灾害解释性案例。

## 8. 指标

### 8.1 决策与样本外质量

- 鲁棒目标、常规采购成本、储备金和储备比例；
- 平均、中位数、P90、P95、P99、CVaR95和最大总成本；
- 平均缺货、缺货概率、服务水平；
- 平均浪费、平均应急支出、储备利用率。

### 8.2 算法性能

- 总 wall-clock、主问题、oracle和初始化时间；
- 迭代数、初始和最终场景数；
- 场景复用率、相邻预算活跃集 Jaccard；
- 峰值内存、终止状态；
- 冷启动时间/热启动时间的配对加速比。

运行时间以中位数为主，均值只作为补充。初始化和场景池构造时间必须计入热启动总时间。

## 9. 统计方案

- 配对单位：同一档位、训练种子和预算；
- 描述统计：样本数、均值、标准差、中位数、四分位区间、最小值和最大值；
- 不确定性：10,000次配对 bootstrap，报告95%置信区间；
- 可选检验：Wilcoxon配对符号秩检验；
- 多重比较时同时报告效应量和校正后的 \(p\) 值；
- 失败和超时保留在完成率分母中，禁止仅对成功样本宣称整体加速。

## 10. 公平性和运行控制

- 固定求解器版本、单线程和相同容差；
- oracle 串行作为主结果；若后续实现并行，只能作为独立附加实验；
- 运行期间关闭非必要高负载任务并记录硬件；
- 所有算法使用相同场景、种子和预算；
- 每个 run 保存配置、场景哈希、Git SHA、依赖、硬件、起止时间和终止状态；
- 缓存只能复用完全相同配置哈希的结果；
- 不允许因为结果不理想而更换正式种子。

## 11. 预计主工作量

- E1 金标准：约252个模型求解；
- E2 策略比较：最多1440个训练求解，其中与 E1/E3相同配置应从运行注册表复用；
- E3 冷/热计时：按冻结重复次数最多1296次算法执行；
- E4 样本外：120个方案、600,000次精确补救评价；
- E5：690个唯一单因素求解，加80个交互求解；
- E6：数量由真实数据冻结报告确定。

因此阶段6必须支持断点续跑、配置哈希去重、失败诊断和分批执行。不得用一次长脚本覆盖已有结果。

## 12. 阶段门槛

1. `D0/V1/V2` 扩展式与标准 C&CG全部通过一致性门槛；
2. 所有成功冷/热配对目标一致；
3. 训练和测试场景独立且哈希可追溯；
4. P档按80%完成率逐级启用；
5. 模型比较、性能、样本外、敏感性和失败表均能由脚本重新生成；
6. 每张图都能追溯到结果 CSV、矩阵版本、种子和代码提交；
7. 真实校准轨道完成来源与变量映射审查；
8. 不把超时、失败或热启动变慢的结果删除。

## 13. 冻结与变更

本矩阵在正式训练种子首次运行前允许通过 PR 修订。正式运行开始后，任何预算、种子、档位、指标或容差变化必须：

1. 升级 `matrix_id/schema_version`；
2. 说明原因和受影响实验；
3. 保留旧结果；
4. 不把变更后的结果与原版本无标记混合。
