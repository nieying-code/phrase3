# 阶段6精简正式实验矩阵

## 1. 状态与范围

机器可读配置为 `configs/phase6_experiment_matrix.yaml`，当前版本：

```text
schema_version = 2.1
matrix_id = phase6_streamlined_experiments_v2_1
status = candidate_for_freeze_pending_review
```

本版在精简矩阵基础上加入经 IIS 验证的相对完全补救修订，因此恢复为候选
状态。`candidate_for_freeze_pending_review` 不授权 pilot 或正式种子；
必须先完成修复 PR 复审、用户手动合并与独立冻结。

本次修订不改变内生储备、C&CG 或 SPW-C&CG 算法逻辑，只在公共第二阶段
库存平衡中加入有惩罚的提前处置。P3和P4仍不属于默认执行任务。

### 1.1 库存退出协议 v1

非最大库龄剩余库存允许进入 `early_disposal`，最大库龄剩余库存进入
`expired_waste`。二者均使用既有 `waste_penalty[item]`；
`total_disposal` 为两者之和，兼容字段 `waste` 是
`total_disposal` 的别名。E4 同时报告 `mean_expired_waste`、
`mean_early_disposal` 和 `mean_total_disposal`，不得重复计入成本。

该科学模型修改会改变科学配置、E3 组件和 family 组件指纹。旧 V1 和
family pilot 只作为历史诊断证据，不进入新门槛；本修复 PR 不运行任何
新 pilot 或正式种子。

## 2. 论文必须回答的问题

阶段6集中回答四个问题：

1. 内生储备相对确定性、零储备和代表性固定比例策略，是否改善训练内与
   样本外决策质量；
2. 全场景扩展式、标准C&CG和SPW-C&CG是否得到一致目标；
3. SPW-C&CG是否在保持完整oracle和精确性的同时减少迭代或运行时间；
4. 需求、应急市场、保质期和仓储条件如何改变储备决策与风险表现。

相邻活跃场景Jaccard与加速收益的相关性不再作为预注册假设。极限规模
P3/P4也不再是论文闭环的必要证据。

## 3. 数据轨道

### 3.1 受控合成轨道

这是核心方法论文的必做轨道，用于：

- 小规模精确性；
- 策略比较；
- 算法计时；
- 多物资扩展；
- 样本外评价；
- 机制与敏感性。

生成器协议仍为 `phase6_controlled_synthetic_v1_0`。除删除未使用的
P3/P4档位外，随机引擎、抽样顺序、潜变量载荷、截断规则、物资原型、
价格曲线、容量、惩罚和理论期望口径不变。

### 3.2 真实校准扩展

真实校准不再是核心方法结论的强制条件。若后续获得来源清晰的需求、
价格和供应代理数据，只增加一个V2级案例，并单独审批校准协议；不复制
全套规模与敏感性矩阵。若不增加真实案例，论文必须把结论限定为受控
合成数值证据。

## 5. 精简规模档位

| 档位 | 角色 | 物资 | 时期 | 训练场景 | 正式种子 | 计时重复 | 扩展式 |
|---|---|---:|---:|---:|---:|---:|---|
| D0 | 历史回归 | 1 | 4 | 20 | 开发种子 | 1 | 必做 |
| V1 | 正确性金标准 | 1 | 6 | 50 | 前3个 | 1 | 必做 |

报告角色：

- V1：只报告正确性，不做显著性检验；
- V2：主要推断性结果；

- P2：只作描述统计，不做显著性检验。

P2只有在P1满足联合完成率和运行时间门槛时才启动。

## 6. 预算设计

V1–P2只使用三个正式预算：

```text
0.90 B_ref
1.10 B_ref
1.30 B_ref
```

分别表示预算紧张、中间状态和相对宽松。三个预算提供两次相邻预算状态
传递，足以验证SPW场景复用。D0仍保留阶段3/5的六个历史绝对预算，仅作
回归。

不得在看到正式种子结果后调整预算。若pilot无法覆盖至少两种储备状态，
只能在正式种子开始前升级矩阵版本。

## 7. 策略比较

主策略比较只在V2执行，使用全部完整训练场景独立精确补救重评。六种策略：

1. 确定性均值；
2. 零储备；
3. 固定10%储备；
4. 固定30%储备；
5. 固定50%储备；
6. 内生储备。

删除固定20%和40%，保留低、中、高固定比例曲线。确定性模型的原生目标
不得直接与鲁棒目标比较。

“内生模型不劣于测试固定比例”是可行域包含带来的结构正确性门槛，不作为
经验创新结论。论文重点是样本外缺货、尾部成本、服务水平和储备变化。

## 8. 精确性门槛

扩展式与标准C&CG在D0、V1、V2核对：

```text
absolute tolerance = 1e-5
relative tolerance = 1e-7
```

标准C&CG与SPW-C&CG在全部算法档位核对相同容差，并要求：

- 完整候选场景oracle；
- 全部独立补救求解最优；
- 最终第一阶段方案可行；
- 失败配对保留在失败表和完成率分母；
- 失败配对不得用于条件性加速结论。

## 9. 算法计时工作量

算法比较档位为V1、V2、P1、P2，冷启动和热启动均执行。正式算法执行数：

| 档位 | 计算式 | 次数 |
|---|---|---:|
| V1 | `3 seeds × 3 budgets × 2 algorithms × 1` | 18 |
| V2 | `10 × 3 × 2 × 3` | 180 |
| P1 | `5 × 3 × 2 × 1` | 30 |
| P2 | `3 × 3 × 2 × 1` | 18 |
| 合计 |  | 246 |

相对旧版1296次减少约81.0%。若平均10次C&CG迭代，预计519,000次
补救LP；按200次迭代上限为10,380,000次。按每个单预算墙钟上限直接
求和，E3串行上界为81小时，而旧版为642小时。

其他实验族的冻结数量：

- E1精确性：45个档位—种子—预算方案，扩展式和标准C&CG共90次；
- E2策略比较：180个策略方案、18,000次训练场景独立补救重评；
- E4样本外：90个方案、180,000次独立测试补救评价；
- E5敏感性：55次单因素模型运行加20次交互运行，共75次。

这些仍是上界/估算。正式种子前必须用当前矩阵、runner和E3组件指纹匹配
的pilot测量吞吐量。项目投影总上限为168小时，单实验族上限为72小时；
超过时必须再次修订矩阵，不能直接放行。

## 10. 三层时限

每个档位分别冻结：

1. 单个求解器调用时限；
2. 单算法、单预算完整C&CG墙钟时限；
3. 单算法完整预算序列墙钟时限。

预算序列时限必须等于“该档计划预算数 × 单预算墙钟”。V1–P2为三个预算，
D0为六个历史预算。

外部watchdog超时必须保留：

- 已完成预算；
- 当前迭代日志；
- 当前LB/UB；
- 当前场景池和最坏场景；
- 超时层级和已用时间。

失败、超时或冷/热不一致后，当前预算记录真实状态，后续预算记录
`not_run_after_pair_sequence_failure`。主结果禁止自动重试；诊断重试
必须使用新run ID和`parent_run_id`。

## 11. 样本外评价

样本外主实验只在V2执行：

- 5个训练种子；
- 固定使用正式训练列表前5个，并配对正式测试列表前5个；
- 三个预算；
- 六种策略；
- 每个方案2000个独立测试场景；
- 同一训练种子和预算下各策略共享测试场景；
- 测试集禁止重新优化第一阶段方案。

2000个场景使CVaR95尾部约包含100个场景，兼顾尾部评价与计算成本。

这里的5个训练种子只提供有限、描述性的样本外证据。2000个测试场景提高
的是每个固定方案内部尾部指标的精度，不能替代训练种子这一独立统计单位。
E4只报告配对效应量、描述性不确定区间、可行率和尾部风险轮廓，禁止据此
作强显著性结论；V2的主要推断角色仅适用于使用10个训练种子的算法计时与
主模型比较。

每个方案必须满足：

```text
N_total = N_optimal + N_infeasible + N_solver_failure
```

报告：

- 补救可行率与最优评价率；
- 不可行场景数与求解失败数；
- 均值、中位数、P90/P95/P99、CVaR95和最大总成本；
- 缺货量、缺货概率、需求加权服务水平；
- 浪费、应急支出、储备利用率。

非最优场景不得静默删除。出现不可行或求解失败时，成本与服务聚合指标按
冻结规则置空并单独报告状态；禁止使用任意Big-M伪造成本。零储备的利用率
为`null`，同时记录`zero_reserve_flag`。

## 12. 精简敏感性

敏感性只在V2、预算`1.10 B_ref`、正式训练列表前5个种子上执行。

五个单因素：

- 需求波动；
- 平均应急价格加成；
- 平均应急供应削减；
- 保质期；
- 仓储容量。

每个因素取低、基准、高三个水平，公共基准只执行一次，因此：

```text
1 + 5 × 2 = 11个唯一配置
```

删除价格波动、供应波动、两个相关系数、两个惩罚倍率的主敏感性，以及原
四因素全因子筛选。

保留一个与论文贡献直接相关的`2×2`交互：

```text
保质期 {1, 6} × 供应削减 {0.05, 0.40}
```

使用5个种子，共20次，用于说明易腐库存与灾后供应风险的联合作用。

## 13. 统计规则

独立实验单位是训练种子，不是“种子×预算”，也不是技术重复。

- 技术重复先在同一算法、档位、种子和预算内取中位数；
- 固定预算以训练种子为配对重采样单位；
- 预算序列汇总时，以同一训练种子的整条计划预算为簇；
- 主效应为每个种子内联合成功预算的中位对数加速比，再取跨种子中位数；
- 报告冷完成率、热完成率、联合完成率和条件性加速；
- 条件性加速不得脱离三个完成率单独报告；
- V1和P2禁止显著性检验；
- P1只有5个种子，推断结论必须克制。

95%区间使用10,000次percentile配对/簇bootstrap：

```text
fixed budget seed = 2026090601
budget sequence seed = 2026090602
```

可选Wilcoxon只能使用每训练种子一个配对统计量，不得把预算行当成独立
样本。

## 14. 规模推进门槛

P2的推进同时要求：

```text
joint pair completion rate >= 0.80
max(median cold runtime fraction, median warm runtime fraction) <= 0.75
```

运行时间比例的分母是该档位单算法、单预算墙钟。时间中位数只使用冷热
均最优配对；超时、失败和未运行项不进入时间中位数，但始终保留在完成率
分母。没有联合成功配对时门槛直接失败。

正式P1运行会生成带科学配置、runner和E3组件指纹的
`scale_advancement.json`。正式P2必须在场景生成前验证该文件、来源档位、
目标档位和两项门槛；文件缺失、过期或未通过时立即拒绝运行。

## 15. Pilot与正式授权

pilot训练种子仍为三个独立种子。吞吐投影要求：

```text
V1/V2/P1/P2 × 3 pilot seeds = 12条预算序列
```

新版每条V1–P2序列只有三个预算，且V1/P1/P2只运行一次技术重复，因此
12条pilot合计108次算法执行，工作量显著低于旧版。旧矩阵、旧runner配置、旧E3代码或Codex旧
Python环境生成的pilot不会通过新指纹。

正式执行同时要求：

1. 矩阵状态为`frozen_for_formal_execution`；
2. 12条当前指纹pilot完整且无主结果重复；
3. 各实验族有量纲一致的投影；
4. 计算门槛明确通过；
5. `formal_execution_authorized=true`。

## 16. 可复现性与输出

每个run保存：

- 解析后的配置；
- 训练/测试场景；
- 文件哈希；
- Git提交；
- Python、依赖和Gurobi版本；
- `gurobi_direct`与`Threads=1`；
- 硬件、开始/结束时间；
- 失败和部分进度。

大型结果不得通过PowerShell `ConvertFrom-Json`展开。状态查询统一使用：

```text
python -m src.phase6_status --output outputs --run-id <RUN_ID>
```
