# Phase 6 M2.1 Gurobi版本预检修复交接

## 根因

PR #64合并后首次正式预检在场景生成前停止。实验机确实安装Gurobi/gurobipy 13.0.2，但Pyomo运行时上下文将版本表示为`13.0.2.0`；旧runner只接受字面值`13.0.2`，因此错误拒绝了正确环境。

## 最小修复

预检现在把合法的三段`13.0.2`和四段`13.0.2.0`规范化为同一release triplet `(13, 0, 2)`。其他版本、非零第四段、缺失段或非数字版本仍会拒绝。求解器接口仍必须为`gurobi_direct`，线程仍必须为1。

本PR没有修改模型、科学矩阵、runner配置或求解逻辑。由于受保护runner模块发生变化，E3与family组件指纹按设计变化，PR #64的旧批准指纹无法通过预检。必须在本PR复审合并后另建重新授权PR。

## 停止边界

首次执行尝试只运行了只读预检：输出根目录不存在，场景生成0、Gurobi调用0、pilot run 0、正式run 0、算法性能run 0、M0 E3 run 0。本PR同样不运行任何科学任务。
