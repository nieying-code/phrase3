# Phase 6 M2算法性能补充实验设计（v1.0）

## 目的与证据边界

本设计基于PR #58的最终M2机制证据与PR #77的M0算法性能证据，预注册一个独立的M2算法性能补充实验。研究问题是：在最终双物资M2模型中，精确场景池从`beta=1.1`迁移至`beta=1.3`后，能否在T03条件下产生可靠加速，以及该收益是否相对C0增强。

本PR只冻结设计。没有实现runner，没有生成场景，没有调用Gurobi，也没有授权pilot或正式实验。M0、M2、M2 OOS和M2.1的既有结果均保持只读，不能作为本协议的执行授权。

无论未来M2算法结果方向如何，都必须报告。若\(S_{T03,1.3}\)通过预注册门槛，只支持“M2/T03下存在可靠的模型特定加速”；若\(S_{T03,1.3}\)与配对增强效应\(D\)均通过，才支持“供应中断增强了跨预算热启动收益”。无论结果如何，都不与M0进行“谁更强”的正式效应比较；M0继续作为无中断基准和既有算法证据，M2结果作为模型特定补充证据或适用边界报告。

## 冻结模型与矩阵

使用最终双物资M2：2种物资、6期、共享应急储备池。Pilot使用50个训练场景；正式性能实验使用100个训练场景。预算和仓储容量必须在首次场景生成前独立复算。

| 维度 | 冻结值 |
|---|---|
| 中断档位 | C0、T03 |
| 预算序列 | `beta=1.1 → 1.3` |
| Pilot种子 | `2026091001–2026091003` |
| 正式性能种子 | `2026091101–2026091110` |
| 算法 | 标准C&CG冷启动；SPW-C&CG跨预算场景池热启动 |
| 正式技术重复 | 每个算法、预算、档位和种子3次 |
| 求解环境 | Python 3.12.10，Gurobi/gurobipy 13.0.2，`gurobi_direct`，`Threads=1` |

正式矩阵闭合为：

```text
10个种子 × 2个档位 × 2个预算 × 2种算法 × 3次技术重复
= 240次算法执行
```

每个`seed-profile`构成一条完整预算序列，共20条primary sequence和40个预算配对。标准C&CG在每个预算独立冷启动；SPW-C&CG在`beta=1.1`没有前序预算可复用，只承担序列初始化和正确性作用，在`beta=1.3`只复用同一seed/profile下`beta=1.1`精确识别的场景。每个预算仍使用完整精确oracle，不删除候选场景。

因此，本文直接识别的是：

> 标准C&CG冷启动完整流程 vs SPW-C&CG跨预算场景池热启动完整流程。

不得拆分解释为纯SPW结构效应或纯求解器变量热启动效应。

## 共同随机数与公平比较

同一正式种子的C0、T03以及两个预算共享需求潜变量、需求、应急价格、应急供应和场景顺序；履约率只随中断档位改变。预算不重新生成场景。冷启动、热启动及三次技术重复读取完全相同的联合场景和输入顺序。

每次技术重复必须是新的求解器执行。三次重复先在预算—算法层取中位时间，不能作为三个独立统计样本。

为降低执行顺序偏差，预算索引0采用`cold → warm`，预算索引1采用`warm → cold`，且一个算法的三次重复连续执行。该交替顺序必须写入逐次审计。

## 正确性Pilot

三个全新pilot种子分别运行C0和T03、两个预算以及完整扩展式、标准C&CG和SPW-C&CG，共：

```text
3 × 2 × 2 × 3 = 36次求解
```

Pilot只检查：三种方法目标一致、冷热输入身份一致、完整oracle保留、全部最优、零失败/超时/无效/重复、内存与正式工时投影。Pilot速度方向不得决定是否执行正式矩阵，也不得修改档位、预算、种子或重复次数。

## 主要估计量

对每个种子、档位和预算，先计算：

\[
q_{s,p,b}=
\frac{\operatorname{median}_{r=1,2,3}T^{\mathrm{cold}}_{s,p,b,r}}
{\operatorname{median}_{r=1,2,3}T^{\mathrm{warm}}_{s,p,b,r}}.
\]

只有`beta=1.3`实际接收了`beta=1.1`的精确场景池，因此主要估计量只使用发生跨预算迁移的预算：

\[
S_{T03,1.3}
=\exp\left(\operatorname{median}_{s=1}^{10}\log q_{s,T03,1.3}\right).
\]

`beta=1.1`没有前序预算，不进入主要热启动估计量。它只用于预算序列初始化、正确性检查和端到端流程计时。

确认性的中断增强估计量为：

\[
D=\exp\left(\operatorname{median}_{s=1}^{10}
\left[\log q_{s,T03,1.3}-\log q_{s,C0,1.3}\right]\right).
\]

使用`numpy.random.Generator(PCG64DXSM(2026091299))`对10个种子进行10,000次有放回配对bootstrap，分别报告\(S_{T03,1.3}\)和\(D\)的95% percentile区间。

两个预算的端到端完整流程速度比仅作为次要描述性结果。对每个种子和档位定义：

\[
S^{\mathrm{end}}_{s,p}=
\frac{\widetilde T^{\mathrm{cold}}_{s,p,1.1}+\widetilde T^{\mathrm{cold}}_{s,p,1.3}}
{\widetilde T^{\mathrm{warm}}_{s,p,1.1}+\widetilde T^{\mathrm{warm}}_{s,p,1.3}},
\]

其中每个\(\widetilde T\)均为三次技术重复的中位数。禁止把两个预算速度比的几何平均称为完整流程速度比。其余次要结果包括C0下`beta=1.3`的速度比、迭代数、oracle调用、场景复用率、主问题/oracle时间和采样RSS。

不预注册p值。所有种子层面数值、效应量和置信区间必须完整报告。

## 预注册论文解释规则

只有同时满足以下条件，才可称“在M2/T03条件下观察到可靠的跨预算热启动加速”：

1. 全部正确性门槛通过；
2. \(S_{T03,1.3}\)点估计大于1；
3. \(S_{T03,1.3}\)的bootstrap 95%区间下界大于1。

只有上述可靠加速门槛通过，并且\(D\)的点估计与bootstrap 95%区间下界也均大于1，才可称“供应中断增强了跨预算热启动收益”。

本设计没有预注册M2与M0的跨实验效应比较，因此无论结果如何，都不得声称“M2的加速强于M0”。若可靠加速门槛通过，只能表述为“M2提供了更明确的模型特定效率证据”，M0仍保留为基准。若不通过，M0继续作为主要算法证据，M2必须以扩展结果或局限性报告。正式结果后禁止继续搜索新的参数、种子、档位或规模。
