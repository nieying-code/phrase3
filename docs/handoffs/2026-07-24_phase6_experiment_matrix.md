## 修改内容

### 正式实验矩阵

- 新增7个规模档位：`D0/V1/V2/P1/P2/P3/P4`，从1物资、4期、20场景逐步扩展到5物资、24期、5000训练场景。
- 正式训练和测试分别冻结10个互不重叠的种子，并保留3个独立试运行种子。
- 多规模预算统一改为参考预算倍率，避免绝对预算在不同物资数和时期数下不可比较。
- 冻结确定性、零储备、5个固定比例和内生储备共8种策略。
- 冻结标准冷启动 C&CG 与 SPW-C&CG 的配对比较、公平计时和精确性门槛。
- 独立样本外主实验固定为120个方案、每个5000场景，共600,000次精确补救评价。
- 单因素分析包含11个因素、23个去重配置，并增加4因素两水平的16组合交互筛选。
- 规定配对 bootstrap、描述统计、可选 Wilcoxon、失败保留和80%完成率逐级扩展规则。

### 数据轨道

- 受控合成数据：正确性、性能和机制识别；
- 真实数据校准的合成数据：阶段6外部有效性必做轨道；
- 历史案例：数据完整时的解释性附加轨道。

真实数据执行前必须冻结来源、许可、访问日期、原始哈希、变量映射、缺失处理和事件级训练/测试隔离规则。

### 防漂移

- 机器可读 YAML 和说明文档使用同一矩阵编号；
- 阶段1的旧实验配置和设计文档明确标记为历史草案；
- 新增自动测试检查种子互斥、档位顺序、样本外规模、预算顺序、容差和敏感性基准；
- README 指向阶段6正式矩阵，并明确本提交尚未执行阶段6实验。

## 关键实验决策

- 小规模扩展式只作为金标准，不要求在大规模继续求解；
- 冷/热目标不一致的配对不得进入加速结论；
- 热启动初始化时间计入总时间；
- 正式种子不得用于调参；
- P档按80%成功配对率逐级启用；
- 超时和失败保留在完成率分母中；
- 样本外场景不得参与重新优化；
- 算法性能主表使用受控合成数据，真实校准结果单独报告，避免数据变化污染算法计时解释。

## 已知限制

- 阶段6生成器尚未实现任意时期季节曲线、跨物资共同灾害因子和物资异质性；这些是下一任务的实现前置条件。
- `P3/P4` 是条件启用档位，不保证当前串行 oracle 能在时限内完成。
- 峰值内存采集、断点续跑、运行注册表、配置哈希缓存和统计汇总尚未实现。
- 真实数据源尚未冻结，历史案例也尚未选定。
- 600,000次样本外补救评价计算量较大，阶段6需要批处理和安全断点恢复，但并行结果必须与串行基线分开报告。

## 风险点

- 参考预算定义是否在多物资和不同保质期下保持可解释；
- 规模档位和时限是否与实际硬件匹配；
- 多物资原型是否需要由真实校准替换；
- 计时重复和种子重复是否被错误混合；
- 失败配对是否可能被过滤后夸大加速；
- 单因素基准是否正确去重；
- 测试场景是否可能被训练或调参流程意外读取；
- 真实数据是否存在时间、地区或事件泄漏。

## ChatGPT 审查清单

1. 规模档位是否足以区分正确性、性能和极限测试；
2. 10个正式训练种子、5个样本外训练配对和5000测试场景是否合理；
3. 预算倍率是否覆盖紧预算、转折和宽松预算；
4. 内生储备与固定比例比较是否公平；
5. 冷/热计时是否包括全部初始化成本并保持完整 oracle；
6. 80%逐级启用和失败分母规则是否会产生选择偏差；
7. 11项单因素与4因素交互设计是否足以支撑机制结论；
8. 600,000次补救评价是否在当前求解架构下可执行；
9. 真实数据校准与历史案例是否明确区分；
10. 是否还有任何在正式种子运行前必须冻结的指标或停止规则。
