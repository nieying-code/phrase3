# Phase 6 M2.1 容差最优端点选择设计（v1.0）

日期：2026-08-21

## 结论与边界

本提交只冻结M2.1设计和执行前安全门槛，不运行实验。M2.1不修改M2的
目标函数、约束、激活定义或供应中断机制。它只把两个问题分开：

1. 机制识别仍使用 $R_{\min}^{opt}-R_{\min}^{feas}$ 判断储备是否必需；
2. 部署方案在同一容差最优储备区间内，用全新验证集选择。

PR #61的诊断状态是
`M2_1_candidate_requires_new_freeze_validation_and_test_sets`。该状态只支持
建立候选设计，不是M2.1有效性的证据，也不授权任何运行。

## 冻结科学设计

核心配置保持双物资、6期、$\beta=1.1$、T03、100个训练场景。完整扩展式
先识别：

$$[R_{\min}^{opt},R_{\max}^{opt}].$$

随后只构造三个候选：最小端点、中点和最大端点。每个候选固定储备后，
必须重新优化常规采购；禁止复用其他候选的采购决策。唯一例外是最小端点：
它本身就是M2控制方案，只生成并最终化一次，M2控制和最小候选必须引用
同一个方案制品、采购哈希、储备、训练目标和训练场景哈希。若验证选择最小
端点，M2.1与M2在测试阶段引用同一方案制品，差异必须在冻结容差内为零。
三个候选都必须保持
在原冻结目标容差定义的容差最优面内。

验证集选择顺序固定为：

1. CVaR95最低；
2. 若在 $10^{-5}+10^{-7}\max(1,|z|)$ 容差内并列，平均成本最低；
3. 再并列时储备较少；
4. 完全相同时按最小端点、中点、最大端点的固定顺序。

服务水平只报告，不参与选择。测试集在方案身份最终化之前不可读取。

同一训练—验证—测试三元组只生成一次验证场景集，三个候选必须共享场景
集合、场景顺序、潜变量、需求、应急价格、应急供应和履约率哈希。正式测试
同样只生成一次测试场景集，六种策略共享上述七类身份。任何不一致均为硬
失败，不能进入选择、主要估计量或后续run。

## 唯一主要确认量

主要确认量仅为10个种子三元组上的：

$$\Delta=\mathrm{CVaR95}_{M2.1}-\mathrm{CVaR95}_{M2}.$$

使用种子三元组为独立配对单位，报告配对均值、10,000次配对cluster
percentile bootstrap的95%区间和双侧Pratt-Wilcoxon（后者只作支持）。
只有配对均值小于0且双侧95% bootstrap区间上界也小于0，才记为主要风险
指标获得支持。平均成本、服务水平等均为次要结果，不得用于重新选择方案。
