# Phase 6 M1：常规采购能力扩展模型

## 1. 研究定位

M1 是现有无采购摩擦模型 M0 的独立扩展轨道。M1 只增加可选的灾前常规采购能力上限，不改变易腐库存、应急采购、相对完全补救、预算等式、场景 oracle、标准 C&CG 或 SPW-C&CG 的定义。

关闭采购上限时，M1 直接使用原始 `ProcurementData`，不生成任何新增约束，因此是 M0 的配对控制。M0 已有结果不被覆盖，也不进入 M1 的授权门槛。

## 2. 唯一新增约束

对物资 `i` 和时期 `t`，灾前常规采购为 `x[i,t]`。开启上限时：

\[
0 \le x_{it} \le \overline Q_{it},
\qquad
\overline Q_{it}=\kappa\,\mathbb E[D_{it}].
\]

`E[D]` 使用冻结生成器协议的理论期望，不使用训练样本均值。`kappa` 必须是有限正数。关闭上限时配置为：

```yaml
regular_procurement_cap:
  enabled: false
  kappa: null
```

配置中禁止用 `Infinity` 表示无上限。

预算仍严格满足：

\[
\sum_{i,t}c^0_{it}x_{it}+R=B.
\]

储备额度 `R` 只限制场景内应急采购支出，不作为已发生成本重复加入目标。M1 不增加资金闲置变量，也不通过储备下界、价格扭曲或奖励项制造正储备。

## 3. 机械储备下界

采购能力上限与预算等式可能使部分预算无法投入常规采购。正式机械储备下界由第一阶段 LP 定义：

\[
R_{\min}^{\mathrm{feas}}=min R
\]

满足预算等式、采购上限和全部适用的第一阶段约束。当前结构下同时核验：

\[
R_{\min}^{\mathrm{closed}}
=\max\left\{0,
B-\sum_{i,t}c^0_{it}\overline Q_{it}
\right\}.
\]

若未来增加其他第一阶段约束，LP 结果仍是正式值，闭式值只用于诊断。

## 4. 容差最优储备区间

单次求解返回的 `R` 可能受多重最优解影响。M1 因此在完整有限场景扩展式上识别储备区间。

首先求原目标最优值 `z*`。使用冻结一致性容差：

\[
\tau_z=\epsilon_{\mathrm{abs}}
+\epsilon_{\mathrm{rel}}\max\{1,|z^*|\}.
\]

然后在原模型全部约束和 `z(x,R) <= z* + tau_z` 下分别求：

\[
R_{\min}^{\mathrm{opt}}=\min R,
\qquad
R_{\max}^{\mathrm{opt}}=\max R.
\]

这两个问题必须使用完整扩展式，不能使用 C&CG 最终受限主问题。两端的第一阶段方案还必须通过独立逐场景补救模型重新评价。

稳健自主储备定义为：

\[
R_{\mathrm{disc}}^{\mathrm{robust}}
=\max\{0,
R_{\min}^{\mathrm{opt}}-R_{\min}^{\mathrm{feas}}
\}.
\]

只有所有容差最优方案都需要超过机械下界时，才判定为自主储备激活。报告字段包括求解器返回储备、机械下界、最优储备区间、稳健自主储备及其预算比例。

## 5. 固定自主储备对照

固定策略以机械下界以外的可配置预算为基数：

\[
R(\rho)=R_{\min}^{\mathrm{feas}}
+\rho(B-R_{\min}^{\mathrm{feas}}),
\qquad
\rho\in\{0,0.1,0.3,0.5\}.
\]

`rho=0` 表示零自主储备。每个 `rho` 都建立新模型、固定 `R` 并重新优化灾前采购。关闭采购上限时 `R_min_feas=0`，定义严格恢复为 `R=rho*B`。

## 6. 求解状态和成本口径

M1 沿用项目现有状态分类和 Gurobi-only 约束。补救不可行仍是违反相对完全补救的不变量，求解器失败不能伪装为不可行或成功。提前处置、到期损耗和总处置继续按已合并模型分别记录，且所有库存退出均收取现有正惩罚。

本扩展不改变应急价格和缺货惩罚。开发矩阵中禁止二者联动扫描，以便把观察到的差异归因于采购能力和预算水平。

## 7. 算法一致性

采购上限由公共第一阶段模型构造器添加，因此完整扩展式、标准 C&CG 和 SPW-C&CG 使用相同约束。M1 仍要求：

- 完整扩展式与标准 C&CG 目标在冻结容差内一致；
- 标准 C&CG 冷启动与 SPW-C&CG 热启动目标一致；
- 所有场景报告来自独立补救模型；
- Gurobi/gurobipy 13.0.2、`gurobi_direct`、`Threads=1`，无其他求解器回退。

## 8. 复现边界

M1 使用独立配置版本、科学配置指纹、E3 组件指纹、family 组件指纹、runner 配置指纹、环境指纹、输出根目录和 runner 命名空间。当前状态为设计候选，所有开发、pilot 和正式执行开关均关闭。
