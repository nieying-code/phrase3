# 研究设计（阶段 1 初稿）

## 1. 研究题目与目标

中文题目：固定总预算下灾前常规采购与灾后应急采购协同的两阶段鲁棒优化——基于跨预算场景池热启动的列与约束生成算法。

英文暂定：*Two-stage robust optimization for coordinated pre-disaster and emergency procurement under a fixed budget: A scenario-pool warm-started column-and-constraint generation approach*。

研究目标是建立一个可复现、可验证的有限场景两阶段鲁棒优化框架，在同一总预算内联合决定灾前多期常规采购计划和灾后应急储备金，并评估跨预算复用历史最坏场景能否在不牺牲最优性的前提下加速 C&CG。

## 2. 研究问题

1. 固定总预算中，多少应承诺给灾前常规采购，多少应保留为灾后应急资金？
2. 需求波动、应急价格上涨、应急供应收缩、保质期和仓储容量如何改变最优储备金额与储备比例？
3. 内生储备策略是否优于预先指定的固定储备比例？优势来自缺货、浪费还是采购灵活性？
4. 连续求解递增预算序列时，复用先前预算下的活跃场景与最坏场景，能否减少迭代次数与时间？
5. 场景池热启动在什么条件下有效，何时会因初始主问题过大而失去优势？

## 3. 研究缺口与谨慎创新表述

### 3.1 预算跨阶段内生分配

本文提出显式应急储备金 `R`，把灾前常规采购承诺和灾后应急采购能力放入同一预算约束。相较于人为给定比例，模型输出 `rho = R/B`，使预算分配成为内生决策。

### 3.2 易腐库存与灾后市场风险联合建模

本文扩展多期易腐采购结构，同时考虑库龄、过期、需求不确定、灾后价格、灾后供应上限和仓储容量，刻画“提前持有实物库存”与“保留现金灵活性”的权衡。

### 3.3 跨预算场景池热启动 C&CG

针对预算序列，本文设计 SPW-C&CG：把上一预算最终活跃的场景、历史上成为最坏情形的场景和基础场景用于初始化下一预算受限主问题。完整场景 oracle 始终保留，因此这是一种精确初始化策略，不是场景删减或近似算法。

上述表述不宣称未经系统检索证明的“首次”。阶段 6 前应补充系统性文献检索，区分本项目与多切 C&CG、场景缓存、跨实例 warm start 和参数化鲁棒优化的关系。

## 4. 研究范围与关键假设

- 第一版使用有限训练场景集合 `Omega`；不构造连续预算不确定集。
- 第一阶段和第二阶段优先采用连续变量，使小规模模型可由 LP 精确核对。
- 第一阶段常规采购 `y[k,t]` 是灾前确定的跨期到货计划；灾后不再调整 `y`。
- 场景揭示后，应急采购、分库龄消费、库存、缺货和过期按场景完全适应。
- 单物资是默认实验，但索引与数据接口保留 `k` 维度。
- 常规和应急采购均假设在期初到货；第一版忽略运输提前期。
- 缺货允许发生并受惩罚，因此需求侧始终可行；若预先采购导致容量冲突，补救 LP 可能不可行，C&CG 必须显式识别并加入该场景。
- 第一版不含路线、车辆、供应商选择、机器学习、分支定价或分布鲁棒优化。

## 5. 机制与可检验假设

以下是待实验检验的方向性假设，不作为数学定理：

- H1：内生储备模型的鲁棒目标不劣于任何被测试的固定比例模型。其理由是内生模型可以复制固定模型的常规采购，并把未承诺预算增加到 `R`。
- H2：需求波动或应急价格上升通常提高保留资金的价值，从而提高最优储备比例，但极端应急供应收缩会削弱现金的可用性，可能反而推动灾前采购并降低储备比例。
- H3：保质期缩短和仓储容量收紧通常降低提前持有库存的吸引力，在应急供应仍可靠时提高储备比例。
- H4：总预算增加时最优鲁棒目标不应恶化；储备金额通常增加，但储备比例不必单调。
- H5：相邻预算的关键最坏场景具有持续性，SPW-C&CG 的迭代次数中位数低于冷启动；当关键场景随预算剧烈切换或历史池过大时，时间优势可能减弱。

## 6. 技术路线

1. 生成带季节性、需求-价格正相关和需求-供应负相关的有限训练场景。
2. 实现平均场景确定性模型与固定储备比例模型，验证库存和预算基本约束。
3. 实现全部场景扩展式内生储备模型，得到小规模金标准。
4. 实现逐场景精确枚举的标准 C&CG，与扩展式核对目标和第一阶段解。
5. 实现预算序列 SPW-C&CG，并与每个预算独立冷启动比较。
6. 进行模型比较、敏感性分析和不少于 5000 个独立场景的样本外评价。
7. 用最终代码反向校准模型文档、伪代码和实验报告，避免文档与实现漂移。

## 7. 正确性验证策略

### 7.1 结构测试

- 每个物资、时期、场景、库龄满足流入 = 消费 + 期末库存。
- 最老库龄剩余量只进入过期，不进入下一期。
- 应急采购支出对每个场景均不超过 `R`。
- 常规采购承诺与 `R` 合计不超过或等于总预算，取决于模型变体。
- 场景补救变量只依赖对应场景，不发生跨场景串联。

### 7.2 算法一致性测试

- 小规模扩展式与标准 C&CG 目标值在绝对/相对容差内一致。
- 标准 C&CG 与 SPW-C&CG 对每个预算的最终目标一致。
- 固定种子重复运行的数据、场景哈希和结果一致。
- 增加预算后鲁棒目标不恶化；若违背，先检查求解容差、预算分配和数值缩放。

### 7.3 极端实例

- 零需求：不应出现缺货或应急采购。
- 充分预算与充分供应：缺货应为零。
- 零应急储备：所有 `q` 必须为零。
- 保质期为 1：跨期库存不得保留。
- 极低容量：模型应调整灾前采购，或在未含相应场景的受限主问题后由不可行补救场景纠正。

## 8. 数据与可复现性

- 所有随机过程由配置文件和显式种子控制。
- 训练与样本外测试使用不同种子和独立场景文件。
- 每个场景文件保存需求、价格、供应、种子、生成器版本和参数摘要。
- 每次实验保存解析后的完整配置、Python/包/求解器版本、运行时间、终止状态和结果表。
- 调试规模为 1 物资、4 期、20 场景；小规模验证为 1 物资、6 期、50-100 场景；大规模在模型正确后逐步扩展。

## 9. 阶段 1 已冻结的默认决策

1. 预算规则：内生模型默认采用“常规采购承诺 + 应急储备 = 总预算”，即剩余预算自动进入储备；固定比例模型保留 `R=rho B` 且常规采购不超过其余预算。
2. 主目标：统一货币量纲后的加权成本；缺货惩罚显著高于采购和浪费，但通过倍率与敏感性分析校准，不用任意 Big-M。
3. FIFO：基础模型不引入二进制强制 FIFO；正浪费成本保证至少存在 FIFO 最优解，但当前实现尚未执行“优先消费老库存”的第二级词典序破平局，不能声称求解器返回的每个最优解都严格 FIFO。
4. 最坏场景：第一版逐场景精确求解补救 LP，不使用近似子问题。
5. 热启动：第一版只做场景池热启动；求解器变量 warm start 单独记录，不混入算法贡献。
