# Phase 6 M1 开发矩阵预注册

## 1. 执行状态

开发协议现已冻结为 `frozen_for_development_execution`，但执行仍需显式 CLI 授权。冻结 runner 的本次 PR 不运行任何矩阵配置、不生成 M1 科学结果，也不继承 M0 的正式授权。

## 2. 冻结网格

- 档位：V1。
- 开发种子：`2026081101`、`2026081102`、`2026081103`。
- 预算系数 `beta`：`0.9`、`1.1`、`1.3`。
- 采购能力 `kappa`：无上限、`1.5`、`1.3`、`1.2`、`1.1`、`1.0`、`0.8`。
- 配置总数：`3 × 3 × 7 = 63`。

无上限对照使用 `enabled=false, kappa=null`，不使用数值无穷大。

## 3. 每个配置的识别任务

每个配置由 M1 专用 runner 严格串行完成：

1. 最低可行储备 LP；
2. 完整场景扩展式原目标求解；
3. 完整场景扩展式容差最优面最小储备求解；
4. 完整场景扩展式容差最优面最大储备求解；
5. 两个最优面端点的独立逐场景补救重评；
6. `rho={0,0.1,0.3,0.5}` 四个固定自主储备策略，各自重新优化灾前采购；
7. 依次最终化 `result → manifest → registry → projection`，然后才允许进入下一个配置。

因此 `63` 是科学配置数，不是求解器调用数。本次不据此声称任何运行时投影，也没有实际运行其中任何一组。

## 4. 预注册激活定义

数值自主激活：

\[
R_{\mathrm{disc}}^{\mathrm{robust}}/B>10^{-4}.
\]

实质自主激活：

\[
R_{\mathrm{disc}}^{\mathrm{robust}}/B\ge 0.01.
\]

某个相同 `beta-kappa` 组合只有在以下条件全部满足时，才可进入后续正式扩展设计：

- 3/3 开发种子全部最优；
- 没有补救不可行、求解器失败或最优面识别失败；
- 至少 2/3 开发种子达到实质自主激活。

不得根据成本、服务水平、视觉趋势或人工判断挑选配置。若没有组合通过，停止扩展，不继续追逐参数。

即使开发门槛通过，projection 也必须保持 `formal_extension_authorized=false`。

## 5. 执行安全协议

真实开发运行必须同时满足：

- 配置状态为 `frozen_for_development_execution`；
- 命令行显式提供 `--authorize-development-execution`；
- Python、Gurobi、依赖锁、Git tree、源码输入和五类 M1 指纹均通过预检；
- 只使用 `outputs/phase6_m1_procurement_cap_v1`，不得读取 M0 registry 或 projection 授权；
- run ID 不可覆盖，诊断重试必须使用新 ID 和 `parent_run_id`；
- 全局 registry、projection 与单 run 生命周期均使用跨进程锁。

缺少任一条件时，runner 必须在场景生成和 Gurobi 调用前非零退出。

## 6. 未来正式轨道边界

开发门槛通过也不自动授权正式实验。未来正式设计必须另行受审，并至少冻结：

- 5 个新训练种子和 5 个独立测试种子；
- 训练—测试配对规则和样本外场景数；
- 共同随机数；
- 禁止在测试场景重新优化；
- 同批新种子上的无上限直接配对控制；
- 独立 M1 registry、projection、输出根目录和机器审计。
